# FamilyVault 路线图

> 原则：先让「一个家庭真的用起来」，再谈规模。
> 每一项都标注了它解决的真实问题，避免为了功能清单而堆功能。

## ✅ 已完成（2026-10）

- [x] 真实认证：JWT + bcrypt、登录限流、防账号枚举
- [x] 首次部署死锁修复：自动种子管理员与初始邀请码
- [x] 登录页与全站 UI 统一（暖纸质设计系统）
- [x] **家庭空间**：家庭邀请码、成员管理、数据按家庭隔离
- [x] **云端同步**：localStorage 降级为离线缓存，登录即拉取、写入防抖上推
- [x] **冲突保护**：写入带版本号，家人同时编辑按 id 合并，不覆盖对方
- [x] Docker / docker-compose 单容器部署，前端由服务端同端口托管
- [x] GitHub Actions CI：构建 + API 冒烟测试

## 🎯 下一阶段：把「能用」变成「好用」（1-2 个月）

### P0 — 数据安全底线
- [ ] **导出/导入对齐云端键名**：AboutPage 导出已改为全量数据，补「导出即完整备份」的验证
- [ ] **SQLite 落盘改 WAL/定时快照**：sql.js 是整库重写，数据量大后需要迁移 better-sqlite3
- [ ] **上传文件鉴权**：`/uploads` 目前是公开静态目录，家人照片需要带 token 访问
- [ ] 时光胶囊端到端加密（内容服务端不可见）

### P1 — 家庭协作体验
- [ ] 实时同步：WebSocket / SSE，家人 A 记录、家人 B 秒看到
- [ ] 成员细粒度权限：owner / 编辑 / 只读（给长辈只读视图）
- [ ] 采访页接入服务端会话（目前采访记录仍是本地 topicPool，服务端 interview 路由未接前端）
- [ ] 冲突合并 UI：被合并时给用户一个「谁改了什么」的提示，而不是静默

### P2 — AI 采访真接入
- [ ] 服务端流式输出（SSE），打字机效果
- [ ] Whisper 语音转文字 + 音频存储（上传目录鉴权后打通）
- [ ] 对话自动提取实体 → 图谱/地图（`extractEntities` 目前是 TODO 空壳）
- [ ] 「AI 采访」未配 key 时在 UI 明示「演示模式」，不要让用户以为坏了

## 🌱 更远：增长与生态（3 个月+）

- [ ] PWA 离线完整可用 + 安装引导
- [ ] 微信小程序端（老人最可能用的入口）
- [ ] 家史书导出（PDF/打印排版，把数据库变成一本真的书）
- [ ] 多家庭：一个人同时属于多个家庭（父母家/祖父母家）
- [ ] i18n：繁体中文、英文

## 🧭 不做清单（同样重要）

- ❌ 不做社交/信息流 —— 家庭记忆不是内容平台
- ❌ 不做广告或数据变现 —— 家史数据比用户敏感一个数量级
- ❌ 不追求全功能覆盖 —— 每个功能都要过「除夕夜场景」：老人拿着手机会不会用
